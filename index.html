Two ways in

Tag at the ground. Start the XbotGo recording, then hit Start clock here at the same moment. Tap a pad whenever something worth talking about happens. No watching the phone, and the work is done by the time you're back in the car.

Or tag from the sofa. Skip the sideline entirely. Load the match in Studio, press play, and hit the category buttons under the video — or the letter keys Q W E R T Y, which sit under your left hand so your right stays on the transport. No clock, no offset, no syncing: marks land against the video's own timeline.

The lag box next to the tag buttons winds each mark back a second to allow for the fact you press after you've seen the thing. Raise it if your marks keep landing late. It only applies while the video is playing — if you've paused to place a mark precisely, the playhead is taken as read.

Watching at 1.5× or 2× and tagging as you go covers a 70-minute game in about forty minutes, which is still slower than tagging live. The sideline route stays the quicker one. This is the better route when you didn't tag on the day, when someone else filmed it, or when you want a second pass over a game you've already been through.

You can mix them freely — tag live, then add more on review. Marks from both land in the same list.

The rest of the workflow

  • At the ground: start the XbotGo recording, then hit Start clock here at the same moment. Tap a pad whenever something worth talking about happens. That's it — no watching the phone.
  • Half time: if the camera keeps recording through the break, leave the clock running too — they have to stay in step. Only pause the clock if you also stop the recording, and resume both together. Pausing keeps the time; it never resets, and it survives the browser reloading.
  • At home: Studio tab, drop in the match file, load your marks. Every mark becomes a clip with sensible in and out points.
  • Off by a few seconds? Nudge Sync offset until the first clip lands right. It shifts every mark at once.

What the research says

  • Telestrated clips lifted player recall to 84% against 52% for plain clips — but only when used on key points. Drawing on everything drowns the message.
  • Keep clips to 30–60 seconds. One idea per clip.
  • Keep colour meaning fixed: blue is always us, red is always them. Coaches who change colours make clips harder to read.
  • Burn the markup in before sending. A clip shared on WhatsApp has to carry its own message.
  • A caption of around fifteen words roughly doubles what a clip achieves. The video shows the moment; the words say what to look for.
  • Ask before you tell. "What options did you have here?" beats "you should have played it wide."
  • Favour positive framing, and don't get too precise — at ten years old, one clear idea beats five accurate ones.

Tools

  • Spotlight dims the pitch and lights one player — the fastest way to say "look here" without a word.
  • Passing option draws a dashed arrow: the pass that was on, not the one played.
  • Space shades an area of grass. Use it for the gap nobody occupied.
  • Marker drops a numbered disc so you can talk about shape without naming kids on a shared clip.

Using it on both devices

Chalkline is one file, so put it somewhere both devices can reach. A free GitHub Pages repo takes about ten minutes and gives you an https address — drop chalkline.html in as index.html and you're done. Once it's on https, the phone will offer Add to Home Screen and it opens full-screen with its own icon, no browser bars.

Each device keeps its own copy of the marks. Moving them across is up to you, and there are two ways.

Handoff code — nothing to set up

  • Phone, after the game: Send to laptop → Copy my marks as a code.
  • Send it to yourself. WhatsApp to your own number works, so does email or Messages.
  • Laptop: same button, paste into the box, Bring in these marks.

A full game of thirty marks compresses to roughly a thousand characters. It's one long string, so make sure it copies whole.

Live sync — one afternoon of setup

If you'd rather it just happen, both devices can talk to a tiny endpoint of your own. Cloudflare Workers has a free tier that will never charge you at this volume. Create a Worker, add a KV namespace bound as CL, and paste this:

export default {
 async fetch(req, env) {
  const cors = {"Access-Control-Allow-Origin":"*","Access-Control-Allow-Methods":"GET,PUT,OPTIONS","Access-Control-Allow-Headers":"Content-Type"};
  if (req.method === "OPTIONS") return new Response(null, {headers: cors});
  const key = new URL(req.url).pathname.slice(1);
  if (!key) return new Response("no session", {status:400, headers:cors});
  if (req.method === "PUT") {
   await env.CL.put(key, await req.text(), {expirationTtl: 60*60*24*90});
   return new Response("ok", {headers: cors});
  }
  const v = await env.CL.get(key);
  return v ? new Response(v, {headers:{...cors,"Content-Type":"application/json"}})
    : new Response("none", {status:404, headers:cors});
 }
}

Put the Worker address in the endpoint field on both devices, give the session a name like geckos-round-7, tick Keep in sync automatically. The phone pushes a few seconds after each tap; the laptop pulls when you come back to the tab and every twenty seconds while it's open.

Marks merge rather than overwrite. Each mark carries the time it was last edited and the newer one wins, and a phone push can't wipe laptop markup because it carries none. Deleting a mark leaves a tombstone so it stays deleted everywhere. Your video and your drawings never go to the endpoint — only timestamps, labels and captions.

Anyone who guesses the session name can read it, so don't use player surnames.

What survives you closing the tab

Everything except the video itself. Marks, trims, captions and all your drawings save continuously as you work — close the tab, close the browser, come back tomorrow, it's all there. There's no save button because there's nothing to forget to press.

The video can't be stored (it's gigabytes sitting on your disk), but Chalkline remembers which file it was. Come back and the drop screen offers Reopen last match — one click, no folder navigation. Chrome and Edge only; Safari makes you pick the file each time. If you've moved or renamed the file since, it'll ask you to find it again.

The one thing that doesn't survive: an export in progress. Recording happens in real time in the tab, so switching away mid-export can stall it. Start an export when you're ready to leave it alone.

The whole-game reel

Compile all clips into one video plays every clip in order and records the lot as a single file — title card, freeze frame with your markup, then the action, clip after clip. Ordered by when they happened in the match, so it plays back as the game's story.

It records in real time. Twenty clips is roughly ten minutes of watching your own screen do the work, and the tab has to stay open and visible. Worth starting while you make a coffee.

For a long reel the ffmpeg route is more reliable and much faster, since it copies rather than re-records. Save session + ffmpeg cuts now writes the join command as well as the individual cuts. That gives you a clean H.264 MP4 — but it carries the trims only, not the markup, so it's the right choice for a plain highlights reel and the wrong one for a teaching reel.

How a marked-up clip saves

Your drawings are stored as shapes against the clip, not painted onto the video — which is why you can come back and edit or delete them. They only become part of the picture at export, when they're burned in permanently so the clip carries its meaning to whoever you send it to.

Markup shows controls how much: freeze frame only puts the arrows on the held still and then lets the action run clean, which is usually what you want. Whole clip keeps them on screen throughout — useful for a zone that stays relevant, cluttered for an arrow that doesn't.

Getting a proper MP4

Export clip gives you a WebM recorded in the browser — fine for WhatsApp on Android, occasionally fussy on iPhone. Save session + ffmpeg cuts writes a text file of exact cut commands so you can produce clean H.264 MP4s:

ffmpeg -ss 412.5 -i match.mp4 -t 14 -c:v libx264 -crf 23 -vf scale=1280:-2 clip_03.mp4

Privacy

Everything runs in the page. The video is read from disk with a local object URL and is never uploaded. Marks and markup save to this browser only. Save the marks file if you want a backup.
